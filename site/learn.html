AI basics, in plain English

The questions people ask us about AI, answered without the jargon or the hype. Every question has its own link: click it to copy an address that opens straight on that answer, ready to send to whoever asked.

Models

What is a model? link

In short: the trained "brain" behind an AI product. A very large file of numbers that reads text (and often images) and predicts what should come next.

A model learns by being shown enormous amounts of text and code until it gets very good at continuing them. That is how it learns to answer questions, write code and follow instructions. On its own it can't browse, run anything or remember you between conversations: it reads what it is given and writes a reply.

ChatGPT, Claude and Gemini are apps. GPT-6.1 Sol, Claude Opus 5.5 and Gemini 4 Argon are models inside them. WizardIndex ranks the models.

What are tokens and the context window? link

In short: models read and write in tokens, chunks of about three-quarters of an English word. The context window is how many tokens a model can see at once.

Everything the model knows about your task has to fit in that window: your instructions, the conversation so far, any files it has opened and its own reply. Anything outside the window it simply doesn't see. APIs charge per token, usually per million, and output costs more than input. A long agent session can easily get through millions of tokens.

What do "reasoning" and "effort" mean? link

In short: many models can think before they answer, writing out working you usually don't see. The effort setting (low, medium, high, xhigh, max) controls how much thinking they're allowed.

More effort usually means better results on hard problems, but slower and more expensive answers, because thinking tokens are billed like any other output. That is why leaderboards often list one model several times, and why WizardIndex notes the setting behind every result.

What is the difference between a local model and an online one? link

In short: an online model runs on the provider's servers and you reach it over the internet. A local model runs on your own computer: you download its weights (that file of numbers) and run them yourself.

Only open-weight models can run locally: families like Qwen, DeepSeek, Llama, Mistral, Gemma, GLM and Kimi publish their weights. The flagship models from Anthropic, OpenAI and Google are closed and online only. Local models are usually quantized, compressed to fit in memory at some cost in quality. Ollama and LM Studio are the easiest ways to start.

Agents

What is an agent? link

In short: a model put in a loop with tools, so it can act instead of only answering: read files, run commands, search the web, edit code, and keep going until the job is done.

A chatbot answers your message and stops. An agent takes a goal ("fix the failing test"), decides on a step, takes it, looks at what happened and adjusts, over and over. Claude Code, Codex, Gemini CLI, Cursor's agent and Devin are well-known coding agents.

What does "agentic" mean? link

In short: work where the model acts on its own over many steps, using tools, rather than giving a single reply.

An agentic coding task can run for hours: explore a codebase, change ten files, run the tests, fix what broke. A model can be brilliant in a chat and still be poor at this, because it has to plan, notice its own mistakes and not wander off. That is why WizardIndex scores agentic work as its own skill (the Agent column on the rankings).

What is a harness? link

In short: the program around the model that turns it into an agent. It sends the model the task and a list of tools, runs the tools the model asks for, feeds the results back and decides when to stop.

Agent = model + harness. Claude Code, Codex, Gemini CLI, Cursor, Aider, OpenCode and mini-SWE-agent are all harnesses. The harness matters a lot: the same model can score more than ten points apart on one benchmark in two different harnesses. That is why leaderboards like Terminal-Bench list the agent next to the model, and why WizardIndex shows it beside each result.

How do agents work with models? link

In short: the harness and the model take turns. The model decides what to do next; the harness actually does it.

Yougive a task
→
Harnessruns the loop
⇄
Modelpicks the next step
⇅
Toolsfiles, terminal, web, MCP
  1. You give the harness a task.
  2. The harness sends the model your task, its standing instructions (the system prompt) and a description of every tool it may use.
  3. The model replies with either an answer or a tool call: a structured request like "run npm test" or "open src/app.js".
  4. The harness runs that tool, often after asking your permission, and sends the result back to the model.
  5. Repeat until the model says it's done, or the harness stops it.

The model never touches your computer itself. It only writes text; the harness decides what actually runs. That is why a harness's permissions matter so much: see Security.

Using models

How do I connect a model to a harness? link

In short: a harness needs three things: where the model is, which model you want, and who pays.

What it isExample
WhereThe provider's address (the "base URL")https://api.anthropic.com, or http://localhost:11434/v1 for Ollama on your machine
WhichThe model's id, from the provider's model listWhatever the provider calls it; the harness usually offers a menu
Who paysAn API key, or signing in with a subscriptionA secret key from the provider's console; local models need none
  • A lab's own harness (Claude Code, Codex, Gemini CLI): sign in with your subscription, or paste an API key from the same lab.
  • Open harnesses (Aider, OpenCode, Cline and many more): pick a provider, paste its API key and choose a model.
  • Local models: run Ollama or LM Studio. They serve the model at a local address that speaks the same language as OpenAI's API (http://localhost:11434/v1 for Ollama, http://localhost:1234/v1 for LM Studio). Point any harness that supports "OpenAI-compatible" providers at that address.

Because so many providers copy OpenAI's API format, a harness that lets you change the base URL can usually talk to almost any model.

API use is billed per token and is separate from chat subscriptions like ChatGPT Plus or Claude Pro. Some harnesses accept a subscription instead, and for heavy use it can be far cheaper: the Thrift column on the rankings accounts for that. An API key is a password that spends your money, so keep it secret: see Security. More places to start, and what each is good for, are on Tools.

Giving agents more abilities

What are tools? link

In short: the actions a harness lets the model take: read a file, run a command, search the web, call a service.

The model can only use the tools it is given. A chat app might give it web search and nothing else; a coding agent gives it your files and a terminal. Every tool is both an ability and a risk, which is why good harnesses ask before running anything that changes or sends something.

What is MCP? link

In short: the Model Context Protocol, a standard plug for giving agents new tools and data. An MCP server wraps something (GitHub, a database, your calendar, a browser) so any agent that speaks MCP can use it.

Before MCP, every harness needed its own integration for every service. Now a service can ship one MCP server and it works in Claude, ChatGPT, Cursor, VS Code and most coding agents. Anthropic started it in 2024 as an open standard, and it has since been adopted across the industry.

A server can run on your own machine or remotely, and you add it in the harness's settings. Each one adds tools the model can call and text the model will read, so only add servers you trust: see Security.

What are skills? link

In short: a skill is a folder of instructions, sometimes with scripts and templates, that teaches an agent how to do one kind of task: your team's release checklist, how to build a spreadsheet, your house style.

The agent only sees each skill's name and one-line description until a task calls for it, then reads the full instructions. So you can install many skills without filling up the context window. A skill is plain files (a SKILL.md plus whatever it needs), which makes skills easy to write, share and read before you install one.

MCP and skills work well together: MCP gives an agent new abilities, and skills give it the know-how to use them well.

Reading the rankings

What is a benchmark, and why do leaderboards disagree? link

In short: a benchmark is a fixed set of tasks with a fixed way of scoring, so models can be compared fairly. Leaderboards disagree because they test different things, in different harnesses, at different effort settings.

A score only means something next to how it was measured: which tasks, which agent, which setting, how many tries. Benchmarks also go stale. Once a test's answers leak into training data ("contamination"), scores rise without models getting any better. WizardIndex prefers fresh or private tests and keeps the receipts for every number: see How it works.

Quick glossary

Frontier model
One of the most capable models available right now, usually from a big lab.
Open weights
A model whose weights are published, so anyone can download and run it. Not always fully open source: the training data and code usually aren't.
Quantization
Storing a model's numbers with less precision so it fits on smaller hardware. Smaller and faster, a little less capable.
Fine-tuning
Training an existing model a bit further on your own examples to change its behaviour.
Inference
Running a model to get an answer, as opposed to training it.
System prompt
Standing instructions the app or harness gives the model before your message: its role, rules and tools.
Hallucination
When a model states something false with confidence. The Truth column on the rankings measures how often models do it.
Multimodal
A model that handles more than text, like images, audio or video.
RAG
Retrieval-augmented generation: looking up relevant documents and putting them in the context window before the model answers.
